# Steven-AI-
Steven AI 開発進捗・引き継ぎ資料

最終更新：2026年10月18日

1. プロジェクト概要

Steven AI は、Androidスマートフォン向けのAIアシスタントアプリ。

開発環境が整うまでは、主にGoogle Pixel 7aを使って開発の準備を進める。将来的にはAPKを作成し、自分や家族のスマートフォンにインストールして使用する。

Google Playでの一般公開は必須ではなく、まずは自分と家族が使えるアプリを完成させることを優先する。

2. 実装したい機能

- 音声によるAIとの会話
- AIチャット
- Web検索
- テキスト、メモ、HTML、Pythonなどのファイル作成
- Steven AI自身のソースコードの作成・編集
- 起動時の認証機能
- 不正アクセス対策
- AIの利用回数・利用料金の上限設定
- 危険性が疑われるWebサイトやファイルへの警告
- 将来的な音声ウェイクワード対応

安全性に関する機能は、Androidの権限やOSの制限を守りながら実装する。すべてのウイルスや危険なサイトを検出できると保証しない。

- Androidアプリの基本画面
- 音声認識による入力

- バックエンドへの質問送信

- Web検索ツールを利用するバックエンドの試作コード
- 「ヘイスティーブン」などの音声を検出するウェイクワード試作機能

未確認・未完成の点

- APKのビルドと実機動作は未確認
- バックエンドは実際のAPIを使った動作確認が未完了
- バックエンドのURLは仮の値
- APIキーの設定とサーバーへのデプロイが必要
- ウェイクワードは常時動作を保証するものではない
- ウェイクワード検出後の画面遷移や音声入力の再開に改善が必要

実装済みのコードが存在することと、機能が正常に動作することを区別する。

5. 次に作るバージョン：v0.4

優先順位1：初回起動時のパスワード認証

- 初回起動時にパスワード入力画面を表示
- 正しいパスワードが入力されたら認証済み状態を保存
- 2回目以降は通常の画面を表示
- アプリのデータ削除や再インストール後は、再認証が必要になる設計
- パスワードをソースコードやGitHubに平文で公開しない
- アプリ内にパスワードを直接埋め込む方式には限界があるため、重要なデータやAPIを守る仕組みとは分けて考える

優先順位2：バックエンドの保護

- APIキーはAndroidアプリではなくサーバー側で保管
- サーバーへのアクセス認証を実装
- 無制限にAPIを呼び出せないようにする
- 必要に応じて利用回数制限、レート制限、ログ記録を実装
- API利用料の予算上限やアラートを設定
- 家族だけで使う場合に適した認証方法を検討する

アプリの初回パスワードだけでは、サーバーへの不正アクセスは防げない。

優先順位3：既存機能の維持

- 音声入力
- AIチャット
- 回答の音声読み上げ
- Web検索
- バックエンドとの通信

新機能を追加した後も、既存機能が壊れていないか確認する。

7. 開発時の重要なルール

1. 既存のソースコードを確認してから変更する。
2. 変更前にバックアップを作る。
3. APIキーやパスワードをGitHubに公開しない。
4. ファイルを生成したら、実際に存在することを確認する。
5. ビルドやテストをしていないものを「動作確認済み」と言わない。
6. API利用料金が予想外に増えないようにする。
7. Androidの権限やバックグラウンド実行の制限を守る。
8. 新しいチャットでは、この資料と最新のソースコード・エラー情報を参照してから開発を再開する。

8. 次のチャットで最初に行うこと

1. 最新版の "steven_android_starter_wakeword.zip" またはGitHubに保存された最新のソースコードを確認する。
2. 現在のファイル構成を把握する。
3. v0.4の認証機能から実装を開始する。
4. バックエンドの認証方式と利用上限を設計する。
5. 変更後のファイルを確認し、可能な範囲でビルド・テストする。
6. 更新済みのZIPが実際に作成できた場合にのみ、完成したファイルとして案内する。

この資料は進捗の引き継ぎ用。実際のソースコードやファイルの状態が食い違う場合は、最新のファイルを優先して確認する。
